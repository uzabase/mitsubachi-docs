# segmented-control

segmented-control（セグメンテッドコントロール）は、横並びに配置された複数のセグメントの中から1つを選択するための切り替え型コンポーネントです。選択はその場で即時反映され、確定ボタンなどの追加操作は必要ありません。

## 使いどころと選び方

### 使うべきシーン
- 同一画面内で表示内容やデータのビューを切り替えたいとき（例：グラフの期間切り替え、一覧の表示形式の変更）
- 選択肢が2〜5個の範囲に収まり、どの選択肢も常に表示しておく必要があるとき
- 操作後に確定処理を挟まず即時反映したいとき

### 使わないほうがよいシーン
- 選択肢が6個以上になる場合は、[select-box](./select-box/index.md) などドロップダウン系コンポーネントへの代替を検討します
- 選択によってページ遷移やセクション全体のナビゲーションが発生する場合は、[tab](./tab/index.md) コンポーネントの使用を検討します
- フォーム内での択一入力に使う場合は、[radio-button](./radio-button/index.md) の使用を検討します
- on/off の二択で、トグル的な意味合いが強い場合は、[switch](./switch.md) コンポーネントの使用を検討します

### 他コンポーネントとの違い・使い分け

#### segmented-control と tab の違い
- [tab](./tab/index.md)（section-tab / page-tab）は、ページやセクションのコンテンツエリアそのものを切り替えるナビゲーションコンポーネントです
- 一方 segmented-control は、コンテンツは変えずにその表示方法や絞り込み条件を切り替えることを目的としています。操作の影響範囲が画面全体に及ぶ場合は tab、局所的な表示切り替えにとどまる場合は segmented-control を選びます

#### segmented-control と switch の違い
- [switch](./switch.md) は on/off の2状態を切り替えるコンポーネントです。segmented-control は2〜5個の選択肢を扱え、各選択肢にラベルやアイコンで意味を持たせて並列表示できます
- 意味が対立する2択であっても、選択肢を明示的に示す必要がある場合は segmented-control を使います

## 構成とルール

segmented-control は、複数のセグメントを1列に並べたコンテナで構成されます。
- コンテナ全体は角丸のボーダーで囲まれています
- 各セグメントは等幅またはアイコン固定幅で配置され、左端のセグメントが最初のセグメントとなります
- 選択中のセグメントにはハイライトされた背景とチェックアイコンが表示されます。未選択のセグメントは白背景にテキストまたはアイコンのみが表示されます

### バリエーション・状態

| プロパティ | 値 |
|---|---|
| variant | `text` / `icon` |
| item | `2` / `3` / `4` / `5` |
| viewport | `desktop` / `phone` |
| state | `default` / `hover` / `active` / `focus` / `disabled` |

#### variant（コンテンツ種別）
| variant | 使いどころ |
|---|---|
| `text` | 各セグメントにテキストラベルを表示します。選択中セグメントにはチェックアイコンとラベルが並んで表示されます |
| `icon` | 各セグメントにアイコンを表示します。選択中セグメントにはチェックアイコンとアイコンが並んで表示されます |

#### item（セグメント数）
- 2 / 3 / 4 / 5 の4段階で指定できます

#### viewport（表示環境）
- `desktop`: デスクトップ向けのサイズで表示します
- `phone`: スマートフォン向けのサイズで表示します。phone の方がタップ操作に適したより大きなタッチターゲットが確保されます

#### 各セグメントの状態
- `default`: 通常状態です
- `hover`: マウスポインタが乗っている状態です
- `active`: クリックまたはタップ中の状態です
- `focus`: キーボード操作などによりフォーカスが当たっている状態です
- `disabled`: 操作不能な状態です。選択・未選択それぞれに disabled 状態があります

### コンテンツルール
- **text variant のラベル**: 選択肢の内容を端的に表す短いテキストを使用します。選択肢間で表記の粒度や文体を統一します
- **icon variant のアイコン**: アイコン単体で選択肢の意味が伝わるものを使用します。アイコンのみでは意味が不明瞭な場合は text variant を選択します
- **セグメント数の上限**: 5個を超えるセグメントは配置できません

## 振る舞い
- **クリック／タップ時**: クリックまたはタップしたセグメントが選択状態に切り替わります。選択はその場で即時反映され、送信や確定の操作は発生しません。すでに選択中のセグメントをクリックしても状態は変化しません
- **フォーカス・キーボード操作**: Tab キーでセグメント間のフォーカス移動ができます。フォーカスが当たったセグメントにはフォーカスリングが表示されます。Space キーまたは Enter キーで、フォーカス中のセグメントを選択します
- **状態遷移とフィードバック**: 未選択セグメントにカーソルを乗せると hover 状態になります。クリック中は active 状態になります。選択が完了すると、選択されたセグメントにはハイライト背景とチェックアイコンが表示されます
- **disabled**: disabled に設定されたセグメントはインタラクションを受け付けません。視覚的に非活性であることが表現されます

## Do
- 同一画面内での表示切り替えに使う
- 選択肢を2〜5個の範囲に収める

## Don't
- 選択肢が6個以上の場合に使わない（select-box や tab を検討）
- ページ遷移を伴うナビゲーションに使わない（tab を使う）
- フォーム内の択一入力に使わない（radio-button を使う）

## 役割と目的
- **解決する課題**: 同一画面内で複数の表示モードや状態を切り替える際、選択肢を常に可視化することで、現在の状態と取りうる選択肢をひと目で把握できるようにします
- **UI上での基本的な役割**: ユーザーが選択したセグメントは即時に反映されます。確定ボタンなどの追加操作は必要ありません
- **ユーザーにとっての意味**: どの状態を見ているかが選択済みセグメントのハイライトとチェックアイコンで常に明示されるため、現在地を見失いにくくなります
