# テキストエリア

text-area は、複数行のテキストを入力・編集するためのコンポーネントです。

## 使いどころと選び方

### 使うべきシーン
- 備考、概要、コメントなど、複数行にわたる入力が想定される場合
- 入力内容のボリュームが不定で、ユーザーが自由に文字量を調整したい場合
- 文字数制限がある場合に、現在の入力文字数を視覚的に伝えたい場合

### 使わないほうがよいシーン
- 1行以内に収まる短い入力（氏名、メールアドレス、検索キーワードなど）には [text-field](./text-field.md) を使用します
- ラベルや必須バッジを合わせて表示したい場合は、text-area 単体ではなく text-area-unit を使用します

### 他コンポーネントとの違い・使い分け
- text-field は1行のテキスト入力専用です。text-area は複数行の入力が必要な場面で使用します。ラベルや必須バッジをセットで表示するフォーム項目では、text-area-unit を使用します

## 構成とルール

### バリエーション・状態

| プロパティ | 値 |
|---|---|
| viewport | `desktop` / `phone` |
| size | `medium` / `large` |
| state | `default` / `hover` / `focus` / `error` / `error-hover` / `error-focus` / `disabled` |

#### viewport（表示環境）
- `desktop`：デスクトップ向けのレイアウトで表示されます
- `phone`：スマートフォン向けにレイアウトが調整されます

#### size（サイズ）
- `medium`：標準サイズです
- `large`：やや大きなサイズです。タッチ操作が主なスマートフォン向けフォームや、視覚的な存在感を高めたい場面に適しています

#### state（状態）
- `default`：通常の入力待ち状態です
- `hover`：ポインターがエリア上に乗った状態です
- `focus`：入力欄がアクティブでキーボード入力を受け付けている状態です
- `error`：入力内容に問題がある状態です。helper-text（ヘルパーテキスト）でエラーの内容を伝えます
- `error-hover`：エラー状態でポインターが重なった状態です
- `error-focus`：エラー状態でフォーカスが当たっている状態です
- `disabled`：操作不能な状態です。入力・フォーカスができません

### コンテンツルール

**プレースホルダー**
プレースホルダーは、入力前のヒントや例示として使用します。入力されると非表示になります。必須ではありませんが、入力形式が分かりにくい場合に有効です。

**helper-text**
エラー発生時は helper-text でエラーの理由を伝えます。helper-text は入力エリアの外側（下部）に表示します。

**文字数カウンター**
- 入力文字数に上限がある場合は文字数カウンターを表示します。カウンターは「`現在の入力文字数 / 最大文字数`」の形式で表示します。「残り何文字」ではなく「入力中の文字数」を表示することで、圧迫感の少ない入力体験を提供します
- 最大文字数を超えた場合も入力は続けられます（コピーペーストで貼り付けた際に文字が自動で削除されないようにするため）。超過した文字数はエラーカラーで視覚的に明示します

## 振る舞い
- 入力エリアをクリック・タップするとフォーカスが当たり、テキスト入力が可能になります
- 縦方向のドラッグ操作でユーザーが入力エリアの高さを変更できます。横方向のリサイズはレイアウト規約と衝突するため提供しません
- モバイル（phone）のブラウザではドラッグ操作がないため、リサイズのハンドルは表示されません
- 入力エリアの高さは2行分を最小値とします
- レイアウト崩れが問題になる箇所では、縦方向のリサイズを無効化してもかまいません
- 最大文字数を超えた状態では、カウンターがエラー表示に変わり、入力テキストの超過部分がエラーカラーで示されます

## 役割と目的
- 備考や説明など、1行に収まらない長文をユーザーが自由に入力・編集できる入力欄を提供します
- 入力エリアはユーザーが縦方向にドラッグしてサイズを調整できます
- 1行のテキスト入力には、代わりに [text-field](./text-field.md) を使用します
