# Prohibited / 禁止事項

デザインシステムの一貫性と品質を保つために、以下の使用を禁止します。

---

## カラー

- デザイントークンに定義されていないカラーコードの直接指定（ハードコード）
- 透明度（opacity）を使った擬似的な色の生成（例: `rgba(0,0,0,0.5)` でグレーを表現する）
- ブランドカラーをアクセントや装飾以外の目的で背景全面に使用すること
- コンポーネントに適用されている色を、semantic color 名から推測して別の色で上書きすること（正は Figma のコンポーネント定義。→ 補足）

## タイポグラフィ

- システムフォント以外のWebフォントを独自に追加すること
- `font-size` をピクセル固定値で直接指定すること（トークンを使用する）
- 本文テキストに対する `letter-spacing` の個別調整

## コンポーネント

- 既存コンポーネントと同等の機能を持つ独自コンポーネントの新規作成
- コンポーネントの内部構造（DOM構造）に依存したスタイルの上書き
- ドロップダウン/メニューをネイティブの `<select>`・`<details>` で代用すること（展開リストは menu コンポーネントで構成する。→ 補足）

## アイコン・画像

- デザインシステムのアイコンセット外からアイコンを持ち込むこと
- アイコンに対するカスタムカラーの直接適用（トークンを使用する）
- 装飾目的でのラスター画像の使用（SVGを推奨）

## 補足：背景と具体例

AI によるプロトタイプ生成で繰り返し起きやすい誤りについて、背景と具体例を補足します。

### semantic color 名からの色の推測（カラー）

コンポーネントの色は必ず Figma のコンポーネント定義（`get_design_context` で取得できる値）を正とし、semantic color 名の意味から類推して変更しない。

- 例: `link-tag` のテキストカラーはコンポーネント定義上 `text/regular` である。しかし `text/link` という semantic color が存在するため、「リンクだから `text/link` だろう」と推測してプロトタイプ上で `text/link` に置き換えてしまうのは誤り。定義どおり `text/regular` を使う。

### ネイティブ要素によるメニューの代用（コンポーネント）

`select-box` / `icon-button` / `menu-button` などのクリックで開く一覧は、必ず [menu](../components/menu/index.md) コンポーネント（mockup では `.mi-menu` + `.mi-menu-item`）で構成する。トリガー（`.mi-select` 等）は「閉じた状態の見た目」だけを担い、展開リストは menu で表現する。

- ネイティブの `<select>`・`<option>`・`<details>` はブラウザ/OSが独自UIを描画するため、デザインシステムの見た目が一切当たらない（＝ブラウザデフォルトのメニューが出てしまう）。
- 開閉・外側クリックで閉じる・ESC・位置決めといった振る舞いは CSS に含まれないため、最小の JS を必ず付与する（実装パターンは [mockup/README.md](../mockup/README.md) の「メニューの実装パターン」を参照）。

---

> **Note:** 例外が必要な場合はデザインレビューで承認を得てください。
